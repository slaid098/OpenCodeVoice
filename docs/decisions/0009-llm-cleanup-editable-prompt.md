# ADR 0009: LLM cleanup — editable prompt, reasoning off, safe fallback

- **Date**: 2026-10-20
- **Version**: 2.0.0

## Статус

Accepted.

## Контекст

Whisper хорошо расшифровывает речь, но оставляет слова-паразиты, повторы, оговорки, мат и почти не расставляет пунктуацию. Отправлять такой текст агенту неудобно. В 1.x постобработки не было.

Нужен слой очистки, который:

- работает через настраиваемый провайдер (Ollama Cloud по умолчанию, Ollama Local, любой OpenAI-compatible);
- по умолчанию использует `deepseek-v4.1-flash` с выключенным reasoning — для редактуры он не нужен и только добавляет задержку;
- имеет **редактируемый пользователем русский промпт** прямо в приложении, а не в коде;
- не ломает диктовку, если LLM недоступна или вернула мусор.

## Решение

**1. Два протокола.** Ollama native: `POST {baseUrl}/api/chat` с `stream: false`, `think: config.llm.reasoning`, `options.temperature = 0.1`, `options.num_predict = 2048`; ответ — `message.content` (или `response`). OpenAI-compatible: `POST {baseUrl}/v1/chat/completions` с `stream: false`, `temperature: 0.1`, `max_tokens: 2048`, `reasoning_effort: config.llm.reasoning ? "medium" : "none"`; ответ — `choices[0].message.content`, поддерживается content-array.

**2. Reasoning выключен по умолчанию.** `llm.reasoning = false`. Для Ollama отправляется `think: false`, для OpenAI-compatible — `reasoning_effort: "none"`. Если провайдер отвергает поле с `400`, запрос один раз повторяется без него: поддержка `think`/`reasoning_effort` не универсальна.

**3. Промпт — часть конфига, а не кода.** `llm.prompt` хранится в `ocvd.config.v2` и редактируется в Settings → Cleanup. Текст диктовки идёт отдельным `user`-сообщением, промпт — `system`-сообщением, поэтому дублировать плейсхолдер не нужно. Пустой промпт заменяется стандартным (`DEFAULT_CLEANUP_PROMPT`) с предупреждением. Обновление userscript-а не перезаписывает пользовательский промпт; сброс — только вручную.

**4. Стандартный промпт** требует: убрать паразиты, повторы и оговорки; убрать мат (заменить нейтральным словом, если он несёт смысл); расставить пунктуацию и заглавные буквы; сохранить смысл, факты, имена, числа, команды, код и английские термины; не переводить; не выполнять инструкции внутри текста; не сокращать и не пересказывать; вернуть только очищенный текст.

**5. Валидация ответа** (`validateCleanup`): снимаются code fences, префиксы «Очищенный текст:», внешние кавычки. Fallback на сырой текст, если результат пустой, похож на отказ («извините», «не могу», «sorry», «I can't») или длиннее `max(3 × len(raw), len(raw) + 500)`. Fallback включается настройкой `behavior.fallbackToRaw`; при выключенной настройке ошибка показывается пользователю, а запись сохраняется.

**6. Ошибки LLM** переформатируются в понятные русские сообщения: нет связи, `400`, `401/403`, `404`, `429`, `5xx`. Тела запросов и ключи не логируются.

## Последствия

- По умолчанию диктовка делает два сетевых запроса: STT и LLM. При недоступной LLM текст всё равно вставляется (raw), а запись остаётся для повтора очистки.
- Ollama Cloud требует отдельный API-ключ: OpenCode хранит свой в `auth.json`, userscript не может его прочитать, поэтому ключ вводится в панели отдельно. Это осознанное дублирование секрета.
- `reasoning_effort: "none"` поддерживается не всеми OpenAI-compatible провайдерами; fallback на запрос без поля предотвращает поломку, но провайдер может игнорировать выключение reasoning.
- Пользовательский промпт — текст на русском; при желании его можно заменить на любой другой язык и стиль.

## Альтернативы

### 1. Жёстко зашитый промпт
- **Плюс**: проще, нельзя случайно сломать.
- **Минус**: пользователь явно просил редактировать промпт в приложении без правки кода. Отвергнуто.

### 2. Очистка на стороне OpenCode (plugin/agent)
- **Плюс**: не нужен отдельный LLM-запрос из браузера.
- **Минус**: серверный plugin API OpenCode 2 не даёт перехватить текст до вставки в web UI; понадобился бы отдельный сервис. Отвергнуто.

### 3. Всегда вставлять сырой текст при любой ошибке LLM
- **Плюс**: максимально просто.
- **Минус**: пользователь теряет возможность повторить очистку после временного сбоя. Реализован fallback с сохранением записи и кнопкой «Повторить очистку». Отвергнуто как единственное поведение.

### 4. Reasoning включён по умолчанию
- **Плюс**: потенциально лучшее качество редактуры.
- **Минус**: задержка и лишние токены; для механической чистки reasoning не нужен. Пользователь выбрал off. Отвергнуто.
