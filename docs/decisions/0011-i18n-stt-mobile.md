# ADR 0011: i18n RU/EN, two STT presets, mobile truncate, question mic and re-injection

- **Date**: 2026-10-20

## Статус

Accepted.

## Контекст

После предыдущего релиза накопились пять практических проблем:

1. **Мобильный variant/reasoning.** На Android Firefox длинное название модели занимает весь ряд `[data-slot="composer-controls"]`, и переключатель reasoning уезжает за правый край экрана. На десктопном Chrome всё стабильно, поэтому менять десктоп нельзя.
2. **Только русский интерфейс.** Проект публикуется на GitHub и должен быть пригоден для англоязычных пользователей.
3. **Перегруженные STT-настройки.** Три провайдера и всегда видимое поле Endpoint. При этом для большинства пользователей достаточно встроенного Whisper (Groq), а кастомный URL нужен для OpenAI, прокси и self-hosted.
4. **403 выглядит как неверный ключ.** Провайдеры (OpenAI, Groq) блокируют запросы из Беларуси и других регионов, но старый `formatSttError` маппил любой 403 в ошибку ключа. Пользователь менял корректный ключ и не понимал причину.
5. **Вопросный микрофон и живучесть.** В актуальном OpenCode 2 поле вопроса — `input[data-slot="text-input-v2-input"]` внутри `div[data-slot="question-option"][data-custom="true"]`, а не legacy `textarea[data-slot="question-custom-input"]`; поэтому микрофон в вопросе не появлялся. Кроме того, `MutationObserver` игнорировал мутации, где все узлы — наши, и если OpenCode удалял только нашу кнопку, повторная инъекция не планировалась — микрофон пропадал до случайной следующей мутации.

## Решение

**1. i18n `ru`/`en`.** `src/i18n.ts` содержит два словаря с одинаковым `MessageKey`; `en` типизирован как `Record<MessageKey, string>`, поэтому недостающий ключ ломает typecheck. `ui.language` принимает `auto | ru | en`; `auto` выбирает RU для `ru*`-языков браузера и EN для остальных. `initI18n()` вызывается до регистрации меню и создания UI. Панель настроек применяет язык после сохранения (`setLocale(resolveLocale(...))`), пункты меню Tampermonkey обновляются только после перезагрузки страницы — осознанное ограничение, чтобы не добавлять `GM_unregisterMenuCommand`. Стандартный промпт очистки локализован (`DEFAULT_CLEANUP_PROMPT_RU`/`_EN`); сохранённый пользовательский промпт не перезаписывается.

**2. Два STT-пресета.** `SttProviderId = "groq" | "custom"`. `groq` — встроенный Whisper: endpoint зашит в `STT_PRESETS.groq`, модель хранится в `stt.groqModel` (по умолчанию `whisper-large-v3-turbo`), пользователь вводит только ключ. `custom` использует `stt.customEndpoint` и `stt.customModel`; любой OpenAI-совместимый endpoint, ключ опционален для прокси без авторизации. Кастомные поля не очищаются при переключении на Groq и обратно. Legacy `endpoint`/`model` и `provider: "openai"` читаются только как вход миграции; пустые поля заполняются из `LEGACY_OPENAI_STT`. Любой нестандартный endpoint сохраняется и становится `custom`, а не заменяется стандартным Groq.

**3. Классификация 403.** Порядок: `401` → ключ; 403 с телом про ключ → ключ; 403/451 с региональными паттернами (`unsupported_country_region_territory`, `country, region, or territory not supported`, `not available in your country`, `region is not supported`, `unsupported region`, `unsupported country`) → регион; 403 на `api.groq.com`/`api.openai.com` с `forbidden` → регион; иначе → общий forbidden с советом проверить ключ, прокси или регион. Общая функция `isSttRegionBlock()` используется и в `transcribe.ts`, и в `models.ts` («Проверить подключение» показывает ту же причину). Нельзя маппить любой 403 в регион: прокси с неверным ключом должен получить сообщение о ключе.

**4. Мобильный layout — только CSS.** В `@media (max-width: 767px) and (pointer: coarse) and (hover: none)` внутренний ряд модели получает `width: 100%; min-width: 0`; модель — единственный элемент с `flex: 1 1 0`, её заголовок обрезается многоточием; agent и variant сохраняют `flex: 0 0 auto` и остаются видимыми. `:has([data-action="composer-model"])` покрывает обёртку, прямой-child селектор — fallback. `position: sticky` отклонён пользователем и не используется. Условия `pointer: coarse` и `hover: none` обязательны: одной ширины недостаточно, потому что узкое или увеличенное окно на компьютере тоже попадает под `max-width: 767px`, а менять ряд управления композером на десктопе нельзя. Мышь и клавиатура дают `pointer: fine`/`hover: hover`, поэтому десктопные стили не меняются на любом разрешении.

**5. Вопросный микрофон.** Поддерживаются оба DOM: актуальный (`div[data-slot="question-option"][data-custom="true"]` + `input[data-slot="text-input-v2-input"]` + `[data-slot="question-footer-actions"]`) и legacy (`form` + `textarea[data-slot="question-custom-input"]`). Контейнер выбирается по приоритету: header actions → футер → custom option → legacy form (в 0.9.3 футер опущен ниже шапки: он находится под списком вариантов и часто обрезается нижней границей окна, поэтому микрофон в нём не виден, а шапка всегда на экране). Элементы вопроса ищутся в последнем видимом `session-question-dock`, как `findComposerDock()`: скрытый dock от предыдущего рендера не должен перехватывать кнопку. В футере/хэдере микрофон вставляется перед последней чужой кнопкой, в custom option — сразу после поля. Вставка в `input` и `textarea` идёт через native setter, `setSelectionRange`, `InputEvent("input", { inputType: "insertText", data })` и `focus()`. Отправка в актуальном DOM — клик по последней включённой кнопке футера (игнорируются `[data-ocvd]`, `disabled`, `aria-disabled="true"`), потому что Enter только коммитит кастомное поле и не отправляет вопрос; legacy-путь Enter → `form.requestSubmit()` сохранён.

**6. Живучесть кнопки.** `handleMutations()` планирует повторную инъекцию, если добавлен чужой узел, **или** если удалён узел, содержавший наши элементы, и он уже не `isConnected`. Дополнительно раз в секунду при `document.visibilityState === "visible"` работает heartbeat. Инъекция идемпотентна: при неизменном DOM узлы не перемещаются. Если существующий микрофон видим, а целевой контейнер временно невидим, кнопка не удаляется. Диагностика показывает не только селекторы, но и наличие/видимость кнопок микрофона.

**7. Версия и GitHub.** Версия снижена осознанно: проект ещё не считается стабильным. Репозиторий переименован в `slaid098/OpenCodeVoice`; GitHub — канал установки и обновлений (`@icon`/`@updateURL`/`@downloadURL`). `@name` и `@namespace` не меняются, иначе менеджеры создадут дубликат вместо обновления.

## Последствия

- Все пользовательские строки проходят через `t()`; новые ключи обязаны попадать в оба словаря.
- Легаси-конфиги мигрируют без потери кастомного STT-endpoint; переключение провайдера в UI больше не стирает `customEndpoint`/`customModel`.
- Сообщение о 403 точнее, но классификация основана на известных телах и хостах. Новый прокси с нестандартным телом получит общий forbidden — это безопаснее ложного сообщения о регионе.
- На телефоне название модели обрезается, reasoning остаётся доступным; десктопный layout не изменён.
- Вопросный микрофон работает в обоих DOM и возвращается после перерисовки без reload; heartbeat добавляет один вызов `inject()` в секунду при видимой вкладке.
- `opencode-config` сделан приватным; открепление из pinned выполняется вручную в веб-UI, так как API этого не умеет.

## Альтернативы

### 1. Sticky-переключатель reasoning на мобильном
- **Плюс**: variant всегда на экране независимо от длины названия модели.
- **Минус**: перекрывает контент, конфликтует с bottom-sheet OpenCode и меняет привычный layout; пользователь явно выбрал сжатие названия. Отвергнуто.

### 2. Третий провайдер OpenAI в UI
- **Плюс**: явный пресет для OpenAI.
- **Минус**: OpenAI и так подключается через Custom URL; отдельный пресет снова усложняет настройки и требует объяснять разницу. Отвергнуто в пользу двух понятных вариантов.

### 3. Автоопределение региона на любой 403
- **Плюс**: проще код.
- **Минус**: прокси с неверным ключом получит ложное сообщение о регионе, и пользователь будет искать прокси вместо ключа. Классификация только по известным паттернам. Отвергнуто.

### 4. Автоматическое обновление при сбросе версии
- **Плюс**: пользователю не нужно ничего делать.
- **Минус**: невозможно на уровне userscript-менеджеров: они не ставят версию ниже установленной. Принят сброс версии.

### 5. Удаление legacy-селекторов вопроса
- **Плюс**: меньше кода и тестов.
- **Минус**: часть установленных 2.0.x всё ещё отдаёт старый DOM; без fallback микрофон в вопросе пропадёт. Оба варианта сохранены, селекторы собраны в `SELECTORS`.
